# Task 03: Automated Login Test for a Web Application

## Overview
An automated test suite for a web application's login functionality, written in Python using **Playwright** and **pytest**.

**Demo site tested:** https://the-internet.herokuapp.com/login
**Valid credentials (provided by the site):** `tomsmith` / `SuperSecretPassword!`

## Test Cases

| # | Type | Scenario | Expected result |
|---|------|----------|-----------------|
| 1 | Positive | Valid username and password | Redirected to `/secure`, success message shown |
| 2 | Positive | Logout after a valid login | Returned to login page, logout message shown |
| 3 | Negative | Invalid username, valid password | "Your username is invalid!" |
| 4 | Negative | Valid username, invalid password | "Your password is invalid!" |
| 5 | Negative | Both invalid | "Your username is invalid!" |
| 6 | Negative | Both fields empty | "Your username is invalid!" |
| 7 | Negative | Empty username, valid password | "Your username is invalid!" |
| 8 | Negative | Valid username, empty password | "Your password is invalid!" |

## Design
- **Page Object Model:** the `LoginPage` class keeps all selectors and actions in one place.
- **Parametrized tests:** all negative cases run through a single test function.
- **Patient waits:** timeouts are increased because the free demo server can respond slowly.

## Setup
```
pip install pytest pytest-playwright pytest-rerunfailures pytest-html
playwright install
```

## Run
```
pytest test_login.py -v --reruns 2
```

To generate an HTML report:
```
pytest test_login.py -v --reruns 2 --html=report.html --self-contained-html
```

## Project Files
| File | Purpose |
|------|---------|
| `test_login.py` | The test suite (Page Object + 8 test cases) |
| `conftest.py` | Sets a custom title for the HTML report |
| `report.html` | HTML test report generated by pytest-html |
| `test_run_terminal.png` | Screenshot of the terminal showing all tests passed |
| `test_report.png` | Screenshot of the HTML report |

## Result
**8 passed, 0 failed.** See `report.html` and the screenshots for proof.

## Notes
- `--reruns 2` retries a test up to two times if it fails. This is used because the public demo site is sometimes slow, which can cause timeouts unrelated to the test logic.
- Tests need an internet connection.
